# 有数 · account-bill

在本地电脑运行的个人与家庭记账应用。将不同平台的账单转换成统一格式，再通过 Codex 分类、匹配退款与关联凭证，生成交易明细、账户流水和统计报表。

**技术栈：** React 19、TypeScript、Ant Design、ECharts；FastAPI、SQLAlchemy、SQLite、Alembic。前端按 PC 场景设计，金额以整数分保存，业务服务使用面向对象的结构。

完整功能、业务关系和报表口径见 [软件功能说明](软件功能说明.md)；本地备份约定见 [操作说明](操作.md)。

## 功能

- **账户与账户组：** 资金账户、负债账户、外部往来；家庭和个人分组；期初、对账、合并与解除合并。
- **银行综合账户：** 银行卡、基金与信用卡可统一到一个账户，账户管理展示抵扣欠款后的净余额。原资金分录与资产/负债属性保留，资产负债表分别统计资产和负债；合并后的账户类型决定是否纳入理财分析，银行类型账户不纳入。
- **证券余额与盈亏：** 证券资产账户可直接更新总资产，首次作为期初，之后按新余额与已记账余额差额自动生成理财收益或投资亏损交易，保留更新历史。总资产包含现金与持仓市值；本金转入、转出先记内部转账，余额不变只保留更新记录。
- **多来源导入：** 支付宝 CSV、微信 XLSX、支付宝小荷包 XLSX、招商银行和中国银行文字版 PDF。银行 PDF 直接读取文字层，不支持仅有扫描图片的 PDF。
- **完整导入链路：** 原文件、统一账单、AI 分类文件、匹配与处理结果分别存档，逐笔保留原始字段。
- **幂等与凭证关联：** 平台流水号去重；同一交易的多份凭证关联到一条明细，避免微信银行卡付款重复扣款。
- **内部转账：** 一笔交易对应两个实际资金账户的变动，不计收入或支出。支持明确账户的单侧凭证确认。
- **退款：** 同文件全额退款双方忽略；部分退款生成一笔净支出。未匹配退款可配置为退款收入。
- **分类与标签：** 默认 30 项、最多两级分类，记录收支用途；多级标签补充归属与场景，可选多个。选择父项包含全部后代。标签支持整树归档和恢复：历史引用保留，归档标签从新标签选择和 AI 参考目录隐藏。
- **家庭总览：** 默认首页，按最新有账务数据的整月展示家庭资产负债与收入、支出、理财、配置关注账户的核心信息。资产负债区展示总额、账户组、账户标签三级桑基图，下方统一设置统计区间与账户屏蔽。可切换最近1/3/6个月、1年或指定区间，默认的理财和单账户名单屏蔽开关在“设置 → 分析配置”统一管理，也可临时屏蔽指定账户。关注账户逐个展示独立收支与趋势，总览趋势统一使用曲线图。资产负债按截止日完整余额计算，理财与配置关注账户独立展示，收支屏蔽不把本金和估值混算。统计报表位于侧栏第二项。
- **PC 布局：** 主区使用面包屑与唯一页标题；常用时间筛选常显，高级条件折叠且保留可清除摘要。单账户页采用可搜索的账户侧栏与分析分区，比较表默认收起；统一表格与指标间距，小数据量隐藏无用分页，窄 PC 窗口下账户组上移，列表独立横向滚动。
- **外观主题：** 在“设置 → 账本设置 → 外观与主题”通过页面缩略预览选择自然绿、简洁蓝、纸杏、雾紫、海青、深色或跟随系统。主题即时生效并保存在当前浏览器，表格、弹窗、卡片和图表同步适配。页面切换和操作反馈采用轻量动效，遵循系统“减少动态效果”偏好。
- **二级导航：** 侧栏分为总览、统计报表、账户管理、账务管理、设置；统计报表依次为资产负债表、收支分析、收入分析、支出分析、单账户分析、理财分析、交易方分析、资金流转、统计明细。支持展开和收起，页面跳转自动定位对应子菜单。
- **收入分析：** 位于“统计报表 → 收入分析”，提供收入总额、等长上期比较、按日/月趋势、分类占比、收款账户与交易方排行、大额收入及全部明细；桑基图按“总额 → 直属账户组 → 收入分类”展示，可点击分类筛选该组明细。只统计有效已入账收入，不将证券转入等内部转账本金计为收入。
- **报表联动：** 所有桑基图的节点和连线，以及柱状图的柱子均可查看对应数据。柱图按日期、收付方向、账户组、交易方或分类精确联动；总览曲线可按日期查看收入、净支出及理财收益，三级资产负债桑基图按直属账户组和标签定位账户；关注账户的曲线和收支金额分别联动该账户明细；统计明细的分类柱明确显示分项金额并保留原交易。收入、支出图只收窄当前账户、日期和分类约束，未分类也可精确查看；趋势日期和交易方可组合筛选局部明细。长页面在点击后定位到已更新的明细，已在视野内不滚动；减少动态模式使用即时定位，普通刷新不移动页面。理财、资产负债表沿用明细抽屉；单账户图、账户变动与资金流转图联动对应表格或交易页签。各处提供范围标签、清除和返回入口，不改动账目，分类拆分及线路金额与完整原交易金额明确区分。
- **分析配置：** 位于“设置 → 分析配置”，保存到 SQLite，统一配置大额收入与大额支出的默认门槛、默认屏蔽证券理财账户和单账户分析名单的开关，适用于总览、收支分析、收入、支出及资金流转；支持分别配置收入、支出的额外屏蔽账户；开关自动跟随新账户类型。页面临时筛选不写回配置，重置恢复保存的默认值，合并账户按目标身份归一；仅改变分析范围，不修改账目。“关注账户”名单由总览与单账户分析共用，与默认屏蔽名单分别管理；历史总览名单自动并入关注账户。
- **单账户分析：** 在分析配置中勾选账户后，进入“统计报表 → 单账户分析”，按名单分别展示账户汇总、余额趋势、收支分类、交易方往来及全部账户变动；内部转账本金、证券估值和期初调整单列，并验证期间变动与余额一致。每个账户可选择仅收支、仅交易方或两者都看；旧配置默认两者都看。收支趋势剔除本金转账和证券估值。收支、交易方和余额趋势各自提供本 Tab 下方的联动明细，图表点击后就近查看，筛选独立保留和重置；全部账户变动始终显示完整流水。可配置普通、理财及负债账户，不受家庭收支页屏蔽名单影响；未配置时提供去配置入口。
- **支出分析：** 位于“统计报表 → 支出分析”，按“总额 → 直属账户组 → 一级分类 → 二级分类”绘制桑基图，一级直接记账金额单列“未细分”。点击节点或连线同步筛选当前页金额、趋势与交易明细，提供重置流向入口并保留日期和账户范围；支持等长上期比较、高频交易方、大额付款及分类压减试算。付款、退款分别按实际付款、收款账户归组，合并来源按目标账户处理；净额为负的细类单列抵减。排除内部转账和默认屏蔽的理财账户，试算不修改预算或账目。
- **交易明细排序：** 支持时间、金额、交易对方、描述、账户、分类及状态的升降序排序。对全部筛选结果排序后再分页，部分退款按实际净额排序。
- **收支分析：** 按收支概览、资金进出、账户变动、分类分析、大额分析和收支明细分为六个页签，共用顶部日期与账户筛选，并支持屏蔽证券理财、单账户分析名单或指定账户；大额门槛仅在大额页签展示。趋势和分类点击在各自页签下方展示联动明细，完整收支明细不受趋势局部日期影响；切换页签保留分析状态。提供所选期间每个资金账户的期初、期间增加额、减少额、净变动及期末余额；期内补录的期初独立列示，不计入期间增减或桑基图。展开查看变动构成，以“期初余额＋期初录入＋期间增加－期间减少＝期末余额”核对。整体桑基图按“期间净增加/减少 → 直属账户组 → 账户标签 → 账户”展示，可联动真实分页、排序及局部合计。账户余额变动跟随日期、账户组、账户及账户屏蔽，交易分类及交易标签只筛下方收支统计。保留按日/月收支曲线、分类饼图、大额交易与交易明细；有效收支不计期初和内部转账，部分退款按净支出统计。
- **资金流转：** 提供整体进出、账户组进出、单账户进出及账户间流转线路四种视角；前三者按范围剔除内部互转，线路视角保留双向与组内实际配对。可按日期、账户组（含子组及未分组）、账户查看有效资金进出，切换账户或直属账户组维度，以及全部流转、账户间转账、对外进出视图。桑基图左右分别为转出方和转入方，双向转账和组内互转保留原额，点击联动进出统计、线路和原交易明细。范围内互转分别计入转入和转出，净额相抵；跨范围保留另一端实际账户。期初、估值、账面调整、撤销与冲销排除；合并账户内部抵消保留原交易，无法唯一配对的多方记录独立列示，不伪造转账线路。
- **范围资金进出：** 收支分析另提供整体、账户组和单账户范围的进出模块，只计跨范围的实际资金。整体只看对外进出；账户组包含子组，组内部互转剔除；单账户来自其他自有账户的转入转出计入该账户边界。支持范围比较、“流入/流出 → 范围内账户组 → 资金账户 → 范围外对手”四列桑基图及每个节点/连线的精确交易联动，期初、估值、调整不计实际流转。父组和子组分别计算，不能把重叠范围相加。
- **资产负债表：** 位于“统计报表”的子页，总览也可直接进入。按截止日期和账户组展示资产、负债与净资产。资产提供“总额 → 直属账户组 → 账户标签 → 账户”四列桑基图，标签按目标账户类型归为理财、银行、支付账户、应收款等；负债保留三列分布。线宽表示金额，悬停显示金额及占比，点击节点或连线查看局部账户明细；负数余额单列抵减。使用账户流水累计余额，合并来源去重，保留停用账户余额；期初不完整时提示补全。
- **单账户交易方分析：** 位于“统计报表 → 交易方分析”，账户更多菜单可直接进入。按同名交易方统计收款、付款、累计净额、交易数、首次和最近往来，支持日期、搜索、金额排行及明细钻取；包括退款和转账，证券估值盈亏单列，期初及撤销不计入。
- **理财：** 位于“统计报表 → 理财”，展示整体净收益、估值收益、盈利亏损、账户净收益对比和各账户情况。只统计“证券”“理财”类型资产账户的余额与收益，银行、微信、支付宝等普通账户及其收益不纳入；合并账户按目标类型判断。资产和收益分别提供“总额 → 直属账户组 → 账户”的桑基图；收益按账户净收益区分盈利和亏损，亏损保持负号、以绝对值绘制宽度，两侧不相抵隐藏。支持账户点击钻取、日期筛选、日/月曲线及盈亏/转账明细。入金出金单列本金，理财账户内部互转在整体汇总时抵消。
- **统计与撤销：** 按日期、账户、账户组、分类、标签筛选和导出；单笔与整批撤销保留审计记录并冲回余额。
- **离线 AI：** 应用不调用 AI 接口，不保存模型密钥。分类参考和目录随账单导出，由 Codex 在应用外处理。

## 快速开始

需要 Python 3.9 或以上。仓库提供构建后的前端，直接使用不需要 Node.js。

```bash
git clone https://github.com/huanwang-su/account-bill.git
cd account-bill
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.lock.txt
PYTHONPATH=backend .venv/bin/python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8765
```

打开 <http://127.0.0.1:8765/>。保持服务运行，在终端按 `Control+C` 停止。

macOS 也可运行 `bash 启动记账.command`，脚本会准备 Python 环境并打开浏览器。需要双击启动时先执行 `chmod +x *.command`。

首次运行建立空账本。账本、原始文件和备份位于 `data/`，不会提交到仓库。没有设置期初余额的账户，其金额仅代表已记录的累计变动。

## 工程与本地数据

直接在同一个 `account-bill` Git 工程中开发、启动和提交代码，无需再维护一份运行目录和一份上传副本。

- 源码、数据库迁移、测试和 `frontend/dist/` 纳入 Git。
- `.venv/`、`frontend/node_modules/` 属于本机运行环境，由 Git 忽略。
- `data/ledger.sqlite3` 是默认账本，包含导入文件存档和业务数据；`data/` 内的账本、备份与临时文件均由 Git 忽略，仅保留空的 `.gitkeep`。
- `main` 是默认代码分支，不纳入备份文件；`wh` 是携带数据备份的分支，允许提交 `backups/*.ledger.zip`。两个分支都不提交本地数据库、原始账单和 `.env.local`；其他备份文件、`exports/`、`uploads/`、`logs/` 继续忽略。

启动脚本和后端按工程自身位置定位文件，因此更换工程位置不会建立第二份账本。移动已有工程时先停止服务，将整个工程连同 `data/` 一起迁移，再启动并核对数据；Python 虚拟环境有绝对路径，迁移后需重建或修复。重新克隆源码不会自动还原已有账本，换机器后需导入保存的备份。

## 账本备份与恢复

本地默认备份流程见 [操作.md](操作.md)：双击 `备份账本.command`，自动读取本地 `ACCOUNT-BILL-PWD` 密码，将加密业务备份导出到工程根目录的 `backups/` 并校验。

需要上传数据备份时，在 `wh` 分支提交并推送加密 ZIP；`main` 仅保存代码和说明文档。切换 Git 分支不会自动切换或恢复本地 SQLite 账本。

在“设置 → 数据管理”点击“下载账本备份”，可填写并再次确认密码，下载带密码的标准 `.ledger.zip`；留空则下载不加密的 ZIP。页面填写的密码不会保存，遗忘后无法恢复；建议使用至少 8 个字符。两种备份均包含全部基础资料、账单、交易、账户流水、估值、导入批次、关联历史和业务设置，不包含原始、统一或分类后账单的文件内容。代码从 Git 获取，主题偏好由浏览器保存。

点击“上传备份并校验”后，加密备份会先提示输入原密码，再检查文件校验值、数据版本、字段、唯一编号、外键、逐笔流水平衡和配置结构，并展示新旧账本的记录数量。密码错误、文件损坏或校验失败均不修改当前账本。选择文件不会入库；只有勾选覆盖确认并点击“确认覆盖并恢复”后，才会替换当前工程的全部账本数据和业务设置。恢复不合并旧数据，也不修改程序代码。

加密使用系统原生 ZIP 工具的标准密码保护，可通过系统解压工具输入密码查看 `manifest.json` 和 `data.json`。密码通过私有终端交给系统工具，不放入命令参数、网址或日志；本地默认导出的密码读取 `.env.local`。旧 `.ledger.enc` 备份保留上传恢复兼容，新下载统一使用 ZIP。本机账本、校验临时文件和自动安全副本仍按原方式保存。

恢复前在 `data/backups/` 自动保存当前账本的业务备份和完整 SQLite 安全副本；成功后点击“下载恢复前备份”也可另设下载密码。恢复在单个数据库事务中完成，中途失败回滚。校验后若有新的账本修改、校验超过 30 分钟或已使用该校验，需重新上传校验。

恢复后可查询历史账单、批次和关联记录；省略的历史文件不能下载，未完成的导入需重新上传原账单。重复导入仍按保留的来源编号和关联关系幂等。旧版 `.sqlite3` 完整备份继续支持停服后通过“恢复备份.command”恢复。

## 使用流程

1. 在“账户管理”创建账户、分配账户组并设置期初余额。
2. 在“账单导入”上传原始账单，下载统一 JSON。
3. 将统一账单和附带目录交给 Codex；只编辑分类、标签和匹配决定，保留原事实。
4. 上传分类文件，点击“导入并入账”。账户和金额明确的记录自动入账。
5. 在“交易明细”核对剩余记录，或关联不同来源的付款凭证。
6. 在“统计报表”的“收支分析”“交易方分析”“理财”“统计明细”“资产负债表”子页分析、查询与导出；在“数据”页备份和检查账目一致性。

原始账单、日常交易与账户变动是不同层次。例如微信通过银行卡消费，一条交易明细可以关联两份账单，但只产生一次银行卡变动；内部转账产生转出、转入各一次账户变动。

资产负债表截至所选日期日末，包含期初和撤销冲回，按当前的账户组及合并配置展示。负债账户的负余额转换为正的欠款金额，预付款显示为负数；净资产 = 资产 − 负债。商户、公共记账账户和待核对记录不计入。未补全期初时，报表反映已记录的累计变动，不能据此认定真实资产余额。

## 开发

前端开发需要 Node.js 20 或以上，以及 pnpm。先按快速开始启动后端，再运行：

```bash
cd frontend
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

开发服务器将 `/api` 请求转发到本地后端。生产构建：

```bash
cd frontend
pnpm build
```

后端测试：

```bash
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
```

浏览器测试使用独立临时账本，默认查找 macOS Chrome；也可以通过 `CHROME_PATH` 指定支持该变量的测试脚本。参见 [浏览器测试说明](frontend/tests/README.md)。

```bash
node frontend/tests/bills-e2e.cjs
node frontend/tests/taxonomy-e2e.cjs

```

真实平台文件测试通过 `ALIPAY_SAMPLE` 和 `MULTISOURCE_SAMPLES` 指向本机样例。仓库仅保留合成测试数据，不附带真实账单。

## 数据与规则

- 人民币 CNY；时间按北京时间记录，银行仅有日期的记录保留日期精度。
- 商户统一使用公共记账账户，不计入个人资产。
- 原账单事实和旧文件不覆盖；撤销使用反向分录，避免删除历史资金记录。
- 自动关联采用账号、订单、金额、日期等证据；金额相同本身不足以证明同一笔交易。
- 部分退款按原付款日期统计净支出；当前没有另外提供退款发生日的现金时间线。
- 证券余额更新按时间顺序，不能早于已有流水或余额更新；已有流水但期初未全时需先补全期初。盈亏是总资产相对已记账余额的估值差额，不提供持仓、成本价或已实现收益明细。
- 理财账户净盈亏包括估值变动及该账户已记录的收入、支出与退款；银行等普通账户即使有理财收益分类，也不纳入理财报表。合并账户按目标账户类型判断，基金并入银行后不再单独纳入理财分析。未更新的市场波动不会自动反映，银行与理财账户间转账需先按内部转账记账。
- 交易方累计净额 = 该账户累计收款 − 累计付款，表示资金往来差额；同名合并统计，空白转账交易方使用另一侧账户名，普通空白归“未填写交易方”。不自动猜测不同名称为同一人。
- SQLite 账本只允许一个本地服务同时使用。应用定位为本机单用户工具。

详见 [账单流程](BILL_WORKFLOW.md)、[验证说明](TEST_REPORT.md) 和 [后续工作](TODO.md)。

收支分析的大额分析分为收入、支出两个页签，门槛和排名独立；退款按负值抵减支出。账户变动显示所选范围净值并单列期末资产、负债核对式：屏蔽部分资产后仍包含的负债可能使范围净值为负，该数字不代表期间亏损或完整家庭净资产。

所有区间筛选共用“最新数据所在整月、最近1/3/6个月、1年、指定区间 + 日期 + 重置”，区间由最新已记录账务日期锚定；日期重置保留其他过滤条件，资产负债表保留单一截止日口径。单账户配置分为“默认屏蔽的单账户”和“关注账户”，关注名单同时用于总览和单账户分析，不自动进入屏蔽；历史总览名单兼容合并。总览关注账户展示收入、净支出、内部转入和内部转出四条独立曲线，内部转账不混入收入或支出，可带当前日期跳转至对应单账户分析。范围资金进出桑基图按方向、账户组、账户、对手固定排序，避免账单顺序造成分支交叉。
