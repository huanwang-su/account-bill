# 有数 · account-bill

在本地电脑运行的个人与家庭记账应用。将不同平台的账单转换成统一格式，再通过 Codex 分类、匹配退款与关联凭证，生成交易明细、账户流水和统计报表。

**技术栈：** React 19、TypeScript、Ant Design、ECharts；FastAPI、SQLAlchemy、SQLite、Alembic。前端按 PC 场景设计，金额以整数分保存，业务服务使用面向对象的结构。

## 功能

- **账户与账户组：** 资金账户、负债账户、外部往来；家庭和个人分组；期初、对账、合并与解除合并。
- **证券余额与盈亏：** 证券资产账户可直接更新总资产，首次作为期初，之后按新余额与已记账余额差额自动生成理财收益或投资亏损交易，保留更新历史。总资产包含现金与持仓市值；本金转入、转出先记内部转账，余额不变只保留更新记录。
- **多来源导入：** 支付宝 CSV、微信 XLSX、支付宝小荷包 XLSX、招商银行和中国银行文字版 PDF。银行 PDF 直接读取文字层，不支持仅有扫描图片的 PDF。
- **完整导入链路：** 原文件、统一账单、AI 分类文件、匹配与处理结果分别存档，逐笔保留原始字段。
- **幂等与凭证关联：** 平台流水号去重；同一交易的多份凭证关联到一条明细，避免微信银行卡付款重复扣款。
- **内部转账：** 一笔交易对应两个实际资金账户的变动，不计收入或支出。支持明确账户的单侧凭证确认。
- **退款：** 同文件全额退款双方忽略；部分退款生成一笔净支出。未匹配退款可配置为退款收入。
- **分类与标签：** 默认 30 项、最多两级分类，记录收支用途；多级标签补充归属与场景，可选多个。选择父项包含全部后代。标签支持整树归档和恢复：历史引用保留，归档标签从新标签选择和 AI 参考目录隐藏。
- **交易明细排序：** 支持时间、金额、交易对方、描述、账户、分类及状态的升降序排序。对全部筛选结果排序后再分页，部分退款按实际净额排序。
- **收支分析：** “统计报表”下提供按日/月的收入、支出和净收支曲线，一级/二级分类饼图与明细，大额门槛、收支筛选及金额排行。支持账户组、账户、父分类、父标签和日期筛选，可查看对应交易；部分退款按净支出统计，期初和内部转账不计入。
- **资产负债表：** 位于“统计报表”的子页，总览也可直接进入。按截止日期和账户组展示资产、负债与净资产。使用账户流水累计余额，合并来源去重，保留停用账户余额；期初不完整时提示补全。
- **单账户交易方分析：** 位于“统计报表 → 交易方分析”，账户更多菜单可直接进入。按同名交易方统计收款、付款、累计净额、交易数、首次和最近往来，支持日期、搜索、金额排行及明细钻取；包括退款和转账，证券估值盈亏单列，期初及撤销不计入。
- **理财收益分析：** 位于“统计报表 → 理财收益分析”，支持单个或全部证券账户、日期区间、日/月盈亏曲线与资产曲线、账户盈亏对比、资金转账及盈亏明细。银行等账户的入金/出金单列本金，证券账户之间互转单列，全部证券汇总时内转净额抵消；期初、撤销和其他余额调整不计收益。
- **统计与撤销：** 按日期、账户、账户组、分类、标签筛选和导出；单笔与整批撤销保留审计记录并冲回余额。
- **离线 AI：** 应用不调用 AI 接口，不保存模型密钥。分类参考和目录随账单导出，由 Codex 在应用外处理。

## 快速开始

需要 Python 3.9 或以上。仓库提供构建后的前端，直接使用不需要 Node.js。

```bash
git clone https://github.com/huanwang-su/account-bill.git
cd account-bill
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.lock.txt
PYTHONPATH=backend .venv/bin/python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8765
```

打开 <http://127.0.0.1:8765/>。保持服务运行，在终端按 `Control+C` 停止。

macOS 也可运行 `bash 启动记账.command`，脚本会准备 Python 环境并打开浏览器。需要双击启动时先执行 `chmod +x *.command`。

首次运行建立空账本。账本、原始文件和备份位于 `data/`，不会提交到仓库。没有设置期初余额的账户，其金额仅代表已记录的累计变动。

## 使用流程

1. 在“账户管理”创建账户、分配账户组并设置期初余额。
2. 在“账单导入”上传原始账单，下载统一 JSON。
3. 将统一账单和附带目录交给 Codex；只编辑分类、标签和匹配决定，保留原事实。
4. 上传分类文件，点击“导入并入账”。账户和金额明确的记录自动入账。
5. 在“交易明细”核对剩余记录，或关联不同来源的付款凭证。
6. 在“统计报表”的“收支分析”“交易方分析”“理财收益分析”“统计明细”“资产负债表”子页分析、查询与导出；在“数据”页备份和检查账目一致性。

原始账单、日常交易与账户变动是不同层次。例如微信通过银行卡消费，一条交易明细可以关联两份账单，但只产生一次银行卡变动；内部转账产生转出、转入各一次账户变动。

资产负债表截至所选日期日末，包含期初和撤销冲回，按当前的账户组及合并配置展示。负债账户的负余额转换为正的欠款金额，预付款显示为负数；净资产 = 资产 − 负债。商户、公共记账账户和待核对记录不计入。未补全期初时，报表反映已记录的累计变动，不能据此认定真实资产余额。

## 默认分类

支出有 9 个一级和 14 个二级分类，共 23 项：

| 一级 | 二级 |
| --- | --- |
| 餐饮 | 日常用餐、买菜、饮品零食 |
| 购物 | 日用品、衣物饰品、数码用品 |
| 交通 | 出行、停车 |
| 居家 | 住房、水电 |
| 宝宝 | 用品、衣物 |
| 医疗健康 | 可直接记在一级 |
| 文娱休闲 | 游玩、会员订阅 |
| 缴费 | 可直接记在一级 |
| 未知用途 | 可直接记在一级 |

收入为 7 个一级分类：工资、理财收益、报销收入、红包收入、保险赔付、退款收入、未知用途。

默认关闭账单自动新增分类。旧类别通过映射归并到现行目录，历史分录的分类身份和金额保留；分类路径调整记录版本。手动分类也最多两级。标签可以继续多级，不把支付渠道、平台或账户归属重复建成用途分类。

## 项目结构

```text
backend/
  app/                 领域模型、解析器、业务服务、API
  migrations/          数据库版本与升级
  tests/               金额、账本、导入、关联、分类等测试
  bill_tool.py         离线账单工具
  manage.py            备份恢复工具
frontend/
  src/                 React 页面、树结构与复用组件
  dist/                可直接运行的前端成品
  tests/               使用独立临时账本的浏览器测试
schemas/               统一账单和退款匹配 JSON Schema
data/                  本地账本与备份，Git 忽略
```

主要服务：

| 服务 | 职责 |
| --- | --- |
| `ParserRegistry` / 平台解析器 | 屏蔽 CSV、Excel、PDF 的来源差异 |
| `BillImportWorkflow` | 分阶段存档、发布与批次撤销 |
| `BillService` / `BillPostingService` | 分类版本、明细与资金记账 |
| `TransactionService` / `ReportService` | 平衡分录、冲回、余额与统计 |
| `FinancialAnalysisService` / `BalanceSheetService` | 复用有效交易与流水，提供收支分析和资产负债表 |
| `SecuritiesValuationService` / `CounterpartyAnalysisService` | 证券总资产更新、估值盈亏记录和单账户交易方收付汇总 |
| `InvestmentAnalysisService` | 证券组合收益、本金与内部资金流分离、资产变化核对 |
| `AccountGraph` / 账户配置服务 | 账户合并身份、分组及递归汇总 |
| `CategoryCatalog` / `CategoryGraph` | 两级目录、旧类别映射与分类解析 |
| `TagHierarchy` | 父标签及全部后代的统一筛选 |
| `RefundMatchService` / 转账与凭证服务 | 退款净额、内部转账与多来源关联 |

## 开发

前端开发需要 Node.js 20 或以上，以及 pnpm。先按快速开始启动后端，再运行：

```bash
cd frontend
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

开发服务器将 `/api` 请求转发到本地后端。生产构建：

```bash
cd frontend
pnpm build
```

后端测试：

```bash
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
```

浏览器测试使用独立临时账本，默认查找 macOS Chrome；也可以通过 `CHROME_PATH` 指定支持该变量的测试脚本。参见 [浏览器测试说明](frontend/tests/README.md)。

```bash
node frontend/tests/bills-e2e.cjs
node frontend/tests/taxonomy-e2e.cjs
node frontend/tests/analysis-e2e.cjs
```

真实平台文件测试通过 `ALIPAY_SAMPLE` 和 `MULTISOURCE_SAMPLES` 指向本机样例。仓库仅保留合成测试数据，不附带真实账单。

## 数据与规则

- 人民币 CNY；时间按北京时间记录，银行仅有日期的记录保留日期精度。
- 商户统一使用公共记账账户，不计入个人资产。
- 原账单事实和旧文件不覆盖；撤销使用反向分录，避免删除历史资金记录。
- 自动关联采用账号、订单、金额、日期等证据；金额相同本身不足以证明同一笔交易。
- 部分退款按原付款日期统计净支出；当前没有另外提供退款发生日的现金时间线。
- 证券余额更新按时间顺序，不能早于已有流水或余额更新；已有流水但期初未全时需先补全期初。盈亏是总资产相对已记账余额的估值差额，不提供持仓、成本价或已实现收益明细。
- 理财分析净盈亏包括证券估值变动以及该证券账户已记录的收入、支出与退款。区间初资产 + 本期新设期初 + 银行等本金净转入 + 证券内转净额 + 净盈亏 + 其他余额变动 = 期末证券资产。未更新的市场波动不会自动反映，银行与证券间转账需先按内部转账记账。
- 交易方累计净额 = 该账户累计收款 − 累计付款，表示资金往来差额；同名合并统计，空白转账交易方使用另一侧账户名，普通空白归“未填写交易方”。不自动猜测不同名称为同一人。
- SQLite 账本只允许一个本地服务同时使用。应用定位为本机单用户工具。
